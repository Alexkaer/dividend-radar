# Private strategy workspace

`strategy.html` is the public login shell; strategy results are published only in `data/strategies.enc.json`. Other pages remain public. This GitHub Pages implementation decrypts content locally rather than providing a server session. It has no server-side rate limiting; anyone can download the ciphertext and attempt offline password guesses. Do not publish credentials, raw strategy reports, or API responses.

The single credential pair is held in GitHub Actions secrets `STRATEGY_LOGIN_USERNAME` and `STRATEGY_LOGIN_PASSWORD`; the Eastmoney skill credential is `MX_APIKEY`. Configure secrets via standard-input or a secure GitHub interface, never command arguments. The deployed page contains neither credentials nor the MX key. PBKDF2-SHA256 (600,000 iterations, random 32-byte salt) derives an AES-256-GCM key; every publication uses a fresh salt and 12-byte nonce. The username participates in key derivation. Decrypted contents stay in memory. The browser saves the nonextractable key material handle in IndexedDB after a successful login so returning to the workspace restores the session. Logout clears both the report and the saved handle. The strategy page runs only first-party code with a restrictive CSP and no third-party counters.

The `Daily strategy screen` workflow updates the encrypted website dataset at 01:20 UTC and 06:30 UTC on weekdays (09:20 and 14:30 China time). These are the only automatic strategy runs. GitHub scheduling and data-provider latency can delay completion. Manual dispatch supports a query mode, a pullback-only option and an intraday cutoff for an exact historical re-run. Auction mode evaluates only the previous completed session, labels candidates as auction observations, and cannot call yesterday's reclaim a confirmed current-day signal. Intraday mode uses the specified cutoff, requires current-session data and marks results provisional. Failure leaves the original encrypted snapshot/date intact. Its completion triggers the existing Pages publish workflow; this does not refresh other public market datasets.

Partial pullback queries decrypt the prior report only in the runner's private temporary directory, replace the pullback group, and preserve other strategy groups and their original dates/statistics. Each group records its own as-of time, mode and coverage. The frontend rejects legacy pullback results whose rule version is not `2026-11-10-mainboard-reclaim-v4`; old results cannot be relabeled as the new strategy. Top-five ranking uses each group's date separately, excludes auction-only observations, and removes revised pullback candidates if current price loses the dynamically updated MA5, exceeds 5% MA5 bias, or fails the dynamically updated MA10/MA20 alignment and slope requirements.

The backend calls the official mx-xuangu stock-screen endpoint, shards code prefixes when a result exceeds 200, records interpreted conditions and coverage, and captures each row's official recent-limit-up count. It then calls Eastmoney's public forward-adjusted daily API concurrently for the underlying OHLCV history. A stock is accepted only when its price-derived mainboard limit-up dates reconcile exactly to mx-xuangu's official 20-session count; mismatches are reported as unavailable rather than passed. This keeps the website updater independent, reduces MX daily-data quota pressure, and retains authoritative cross-checking. A supplier quota exhaustion response stops instead of becoming an empty pool; the existing encrypted report/date is retained. No plaintext report, fixed candidate quota, automatic watchlist change or trade is published.

The three views are: revised limit-up pullback recovery (at least two official limit flags within the latest 20 sessions without an upper cap; Shanghai/Shenzhen mainboard non-ST and listed over 365 days; post-limit pullback closes hold MA20; the latest three K-line centers rise; MA10>MA20 and both rise; the pullback once moved below dynamic MA5 and later reclaimed it; current MA5 bias is 0% to 5%), second-board pullback, and revised triple-volume. The pullback rule does not require a bullish engulfing candle and does not automatically exclude a stock merely because its daily gain exceeds 5%. At 14:30, VWAP, five-minute volume expansion, industry linkage, an exact stop, first target, reward/risk and suggested account allocation are recorded. A+ is capped at 10%, A at 5%, per-trade account risk at 0.5%, and total new exposure at 20%. At 09:20 all suggested allocations remain 0% pending intraday confirmation.

The priority panel merges all strategy pools by code and keeps up to five mechanically ranked observations. It requires validated latest Eastmoney quote timestamps and excludes <=-5% loss, broken guards, >8% guard distance and high-risk/unconfirmed-gap/signal-day patterns. A gain above 5% is not an automatic exclusion for the revised pullback pool; its MA5-bias gate remains binding. For that pool, the quote date must match the strategy snapshot date. MA10/MA20 alignment and slopes plus MA5 position/bias are recomputed with the latest price. Scores sum structure (30), distance to the trigger zone (25), guard distance (20), daily volume contraction (15), and current change (10). All five can be absent. No automatic trade follows this ranking.

Login automatically fetches current public Eastmoney quotes with CORS `fetch`; the real-time refresh button repeats it and recalculates ranking, while the separate snapshot button decrypts the latest MX daily report. Only Eastmoney's two quote hosts are allowed by `connect-src`; remote scripts/JSONP are prohibited on this page. No credentials are transmitted to quote endpoints and no decrypted results or quotes are persisted. Source timestamps are displayed independently of daily strategy dates. Intraday quotes more than ten minutes old, future timestamps, and missing fields cannot enter the current ranking. Outside trading hours the panel identifies the latest closing quote rather than claiming a live trade.

Local validation:

```sh
python scripts/test_strategy.py
node scripts/test_strategy_crypto.cjs
node scripts/test_strategy_ranking.cjs
node --check strategy.js
```

To refresh locally, write `--output` to an OS-private temporary directory outside this repo, then call `scripts/encrypt_strategy.cjs` using environment credentials. Never upload the plaintext or include it in Pages artifacts. Never cache private results in public Actions artifacts. Existing ciphertext in Git history remains decryptable with the corresponding old password if credentials are later changed; rotation cannot revoke copies already downloaded.
