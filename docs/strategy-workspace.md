# Private strategy workspace

`strategy.html` is the public login shell; strategy results are published only in `data/strategies.enc.json`. Other pages remain public. This GitHub Pages implementation decrypts content locally rather than providing a server session. It has no server-side rate limiting; anyone can download the ciphertext and attempt offline password guesses. Do not publish credentials, raw strategy reports, or API responses.

The single credential pair is held in GitHub Actions secrets `STRATEGY_LOGIN_USERNAME` and `STRATEGY_LOGIN_PASSWORD`; the Eastmoney skill credential is `MX_APIKEY`. Configure secrets via standard-input or a secure GitHub interface, never command arguments. The deployed page contains neither credentials nor the MX key. PBKDF2-SHA256 (600,000 iterations, random 32-byte salt) derives an AES-256-GCM key; every publication uses a fresh salt and 12-byte nonce. The username participates in key derivation. Decrypted contents and a nonextractable key material handle stay in memory; logout clears the report, reload requires login again. The strategy page runs only first-party code with a restrictive CSP and no third-party counters.

The `Daily strategy screen` workflow queries the revised pullback strategy at 01:15 UTC and 06:40 UTC on weekdays (09:15 and 14:40 China time), and retains the full-strategy 07:45 UTC closing review (15:45 China time). GitHub scheduling and data-provider latency can delay completion. Manual dispatch supports a query mode and a pullback-only option. Auction mode evaluates only the previous completed session, labels candidates as auction observations, and cannot call yesterday's reclaim a confirmed current-day signal. Intraday mode requires current-session daily data and marks results provisional. Failure leaves the original encrypted snapshot/date intact. Its completion triggers the existing Pages publish workflow; this does not refresh other public market datasets.

Partial pullback queries decrypt the prior report only in the runner's private temporary directory, replace the pullback group, and preserve other strategy groups and their original dates/statistics. Each group records its own as-of time, mode and coverage. The frontend rejects legacy pullback results whose rule version is not `2026-11-09-mainboard-bullish-v3`; old results cannot be relabeled as the new strategy. Top-five ranking uses each group's date separately, excludes auction-only observations, and removes revised pullback candidates if current price falls back below all matched dynamically updated averages or fails the dynamically updated bullish alignment/slope requirements.

The backend calls the official mx-xuangu stock-screen endpoint, shards code prefixes when a result exceeds 200, records interpreted conditions and coverage, then calls mx-data query for 40 trading sessions of real historical daily OHLCV and the historical limit-up status (minimum 35 aligned bars). This covers the longest 30-session strategy window without repeatedly requesting excessive history. Omitted entities are retried individually. A supplier quota exhaustion response stops immediately rather than becoming an empty pool; the existing encrypted report/date is retained, with the workflow reporting failure. Report fields include the session, generated timestamp, rule version, coverage, missing-data list, trigger ranges and invalidation levels. No fixed candidate quota, automatic watchlist changes, or trades.

The three views are: revised limit-up pullback recovery (at least two official limit flags within the latest 20 sessions without an upper cap; Shanghai/Shenzhen mainboard non-ST and listed over 365 days; MA5>MA10>MA20 with each average strictly rising versus its own previous-session value; current price strictly above MA5 or MA10 after a prior-session close below that average or a current-session breach), second-board pullback (consecutive limit flags, 3–10 sessions after the break, volume <= half the break-day volume and MA10 support), and revised triple-volume (same-day >=3x preceding volume, bullish >3%, upper-half close, bottom-zone/real-body breakout tracking). For an intraday breach, the dynamic MA at the low tick is calculated from that low and the preceding n−1 closes; a wick merely below the final closing MA does not prove it crossed the dynamic line. Either MA5 or MA10 suffices; no consecutive-board requirement applies to the revised pullback pool. The revised pullback pool has no CNY100m turnover gate; the unchanged second-board and triple-volume pools retain their existing liquidity gates. Triple-volume has no hard moving-average alignment requirement. These are observation rules; sector strength and intraday VWAP acceptance remain explicitly unverified.

The priority panel merges all strategy pools by code and keeps up to five mechanically ranked observations. It requires validated latest Eastmoney quote timestamps, excludes >=5% gain, <=-5% loss, broken guards, >8% guard distance and high-risk/unconfirmed-gap/signal-day patterns. For the revised pullback pool, the quote date must match the strategy snapshot date: a new day's upward cross and MA trend cannot be inferred by replacing yesterday's close alone. Source-day MA alignment and all three slopes are recomputed with the latest price; a failed cross or trend removes the item from current priority rankings. Scores sum structure (30), distance to the trigger zone (25), guard distance (20), daily volume contraction (15), and current change (10); missing volume earns no volume points. A displayed score does not imply sector or intraday confirmation. All five can be absent. No portfolio or trading action follows this ranking.

Login automatically fetches current public Eastmoney quotes with CORS `fetch`; the real-time refresh button repeats it and recalculates ranking, while the separate snapshot button decrypts the latest MX daily report. Only Eastmoney's two quote hosts are allowed by `connect-src`; remote scripts/JSONP are prohibited on this page. No credentials are transmitted to quote endpoints and no decrypted results or quotes are persisted. Source timestamps are displayed independently of daily strategy dates. Intraday quotes more than ten minutes old, future timestamps, and missing fields cannot enter the current ranking. Outside trading hours the panel identifies the latest closing quote rather than claiming a live trade.

Local validation:

```sh
python scripts/test_strategy.py
node scripts/test_strategy_crypto.cjs
node scripts/test_strategy_ranking.cjs
node --check strategy.js
```

To refresh locally, write `--output` to an OS-private temporary directory outside this repo, then call `scripts/encrypt_strategy.cjs` using environment credentials. Never upload the plaintext or include it in Pages artifacts. Never cache private results in public Actions artifacts. Existing ciphertext in Git history remains decryptable with the corresponding old password if credentials are later changed; rotation cannot revoke copies already downloaded.
